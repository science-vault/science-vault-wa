# Resource layout and catalogue cleanup

All resource vault categories and the year-specific assessment view share search, subject / year / pathway / unit or strand / source filters, sorting, grouped companion files, previews, downloads and pagination (10 by default; 25 or 50 optional). The all-resources view includes a type filter. Existing account/page permissions are retained, and separately restricted assessment, exam and textbook collections are not exposed through the general library without their own access permission.

The inventory audit covered 28,427 tracked files beneath resources, exams and textbooks. After filtering temporary/system files and invalid zero-byte teaching files, 25,980 supported source files represent 22,674 distinct content blobs. 3,306 exact duplicate copies display once; their alternate year/subject/source locations remain filterable. Identical bytes are determined from Git blob SHA, not filename guesses. Distinct editable and PDF versions are retained. Valid files are not hidden just because their names contain “copy”.

74 confirmed zero-byte teaching files are removed from the repository. Empty folder markers remain. Temporary/system files are excluded from browsing. Usable files retain their original paths, preserving question-bank images, imported exam references and old download links. Clear placement corrections are made in the catalogue: videos belong in Videos; presentations in worksheet folders belong in PowerPoints; ordinary teaching resources in nested Resources folders are separated from assessment archives. Unknown units are not invented.

RESOURCE-CLEANUP.json records confirmed removals and corrected tab locations. RESOURCE-AUDIT.json gives exact duplicate proof and all source aliases. The audit checks inventory and exact content identity; it does not open and inspect the internal content of every non-empty document.

The shared catalogue is emitted as small category chunks, so a dedicated tab fetches its own data. Both deployment and future resource-upload workflows rebuild it. Upload indexing now reads Git tree metadata rather than checking out the full archive; known file sizes and dates are retained, and unknown values are not fabricated. Empty/junk files cannot re-enter the browser merely because an old manifest still lists them.

Validation: tests/resource-vault.cjs exercises all 12 resource views, catalogue membership / duplicate SHA proof, alternate contexts, search, clearing, pagination, year links and download URL construction. Run with jsdom available: node --experimental-vm-modules tests/resource-vault.cjs. Browser DOM tests mock Firebase access; real account/page permissions still apply on the live site. Full browser visual and document-content inspection was unavailable.
