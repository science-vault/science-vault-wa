ONE-TIME FIREBASE SETUP

Connect your admin account.

The website is ready to use your Firebase Authentication and Firestore account permissions.

  1. Enable email/password login. In your science-vault-wa Firebase project, open Authentication → Get started → Sign-in method, and enable Email/Password. In Authentication → Settings → Authorized domains, add science-vault.github.io.
  2. Create the account database. Open Firestore Database → Create database. Choose production mode and a suitable region. Do not use open test-mode rules.
  3. Publish the permission rules below. In Firestore Database → Rules, replace the rules with this complete file, then click Publish.
  4. Create your owner account. Open Sign up, choose Teacher, and verify your email. On My account, expand Account ID and copy your UID. Existing accounts can finish registration on My account.
  5. Assign the owner in the console. In Firestore Database → Data, create collection admins. Set the document ID to your exact Firebase account UID. Add field enabled, type boolean, value true. Only grant this to your own owner account.
  6. Open the admin page. Refresh My account, then open Account administration. Select an account, tick its pages, and use Approve & save access. Use Save page access to change permissions later, or Suspend all access to block all content pages.

Students receive the configured learning/practice defaults without owner approval. Teachers start pending with no content-page access. Granting a page never grants administrator powers. Login, privacy and legal pages remain available.

Files and source on public GitHub remain public. These rules protect account information and who can edit permissions. Protecting the resource files and page data requires private storage or protected hosting.
